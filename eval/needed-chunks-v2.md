# Needed chunks — docs v2

Frozen map of which **v2** rag chunks contain the facts for each eval task.  
Written from the v2 docs text and the chunker ids below. Not from model output or `results/`.

A set of chunks is sufficient when together they contain every fact the correct answer depends on. The command name cat-status and the answer format are given by the task and do not count as facts.

## Metric: retrieved-sufficient

A rag run attempt is **retrieved-sufficient** if, for **at least one** listed alternative for that task, **all** chunk ids in that alternative appear in the retrieved top-k for the attempt.

- `needs [a AND b]` — one alternative that requires both chunks.
- `OR [c]` — another alternative that is sufficient on its own (or with its own AND set).

## Diagnostics (split facts)

- **T3:** Class filter examples live in `list--filter-by-status-class`; `--json` list form lives in `list--print-the-list-as-json`. The AND alternative covers retrieving both when neither overview/flags chunk is present. Several single chunks already carry the combined `--list … [--json]` form.
- **T4 / T10:** Overwrite vs refuse-overwrite is spelled out in `save--overwrite-an-existing-file-with-force` and the force row of `flags--read-the-complete-flag-table`; the stderr table alone names `--force` but not the full save command, so it is paired with `save--download-the-image-for-a-known-code`.
- **T7:** Chunks that name **505** with exit `2` are sufficient alone. `changelog--read-what-shipped-in-1-0-0` names 505 as a no-image example but not the exit code; `errors--read-the-exit-code-meanings` gives exit `2` for no-image codes but not 505 — hence the AND alternative.
- **T8:** `flags--read-the-complete-flag-table` states `--timeout` only with `--save` but not exit `1`; `errors--read-the-exit-code-meanings` maps usage errors to `1` but not this combination — hence the AND alternative. `save--set-a-download-timeout` and the stderr table each carry both facts alone.
